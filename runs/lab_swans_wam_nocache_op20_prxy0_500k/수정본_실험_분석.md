# 연구실 SWANS 수정본 실험 분석

## 결론

요청한 기능은 별도 연구실 코드 사본에 반영했고 빌드 및 세 종류의 시뮬레이션으로 확인했다.

- migration restore write가 WAM 누적 물리 쓰기량에 포함된다.
- migration 중 read와 write가 같은 queue에서 기다리고, 둘 다 migration 종료 후 실제 SSD backend로 replay된다.
- SSD data cache mode는 `TURNED_OFF`이며 RAID controller에도 별도 data cache를 추가하지 않았다.
- OP를 10%에서 20%로 늘렸다.
- P/E 한도에 도달한 block은 bad block이 되어 free pool에 돌아가지 않는다.
- bad block 및 수명 한계가 확정된 in-flight erase가 OP 예비 block 수를 모두 소비하면 시뮬레이션이 정상 종료된다.

## 1. 구현 기준

### WAM

WAM은 요청 개수가 아니라 512-byte sector 양으로 계산한다.

```text
누적 WAM 쓰기량 = host write sectors + migration restore write sectors
```

host write는 redirection 이후 최종 SSD에 기록하며, migration write는 실제 restore가 발행된 목적 SSD에 기록한다. Logical data가 이동해도 원본 SSD에 이미 생긴 과거 wear는 취소하거나 목적 SSD로 옮기지 않는다.

### 캐시 및 migration 동기화

- workload의 `Device_Level_Data_Caching_Mode = TURNED_OFF`
- migration 대상 hot/cold zone에 들어온 read/write는 동일하게 deferred queue에 저장
- migration 종료 후 모든 요청을 RAID/SSD backend로 replay
- RAM queue에서 write 완료 처리 금지
- migration queue는 데이터 캐시가 아니라 요청 순서를 보존하는 동기화 queue로만 사용

### bad block 및 OP 종료

- erase 완료 시 P/E 한도 확인
- 한도 도달 block: `Is_bad = true`
- bad block: free pool 재삽입 금지, GC/WL 재선택 금지
- OP block 한도: `ceil(physical blocks × OP ratio)`
- 완료된 bad block과 수명 한계 도달이 확정된 in-flight erase의 합이 OP 한도에 도달하면 안전하게 종료

In-flight erase도 포함한 이유는 병렬 GC 중 아직 erase 완료 이벤트만 남은 block들이 이미 OP 예산을 소비하도록 확정되어 있기 때문이다. 이를 제외하면 free pool 고갈이 OP 종료 이벤트보다 먼저 발생할 수 있다.

## 2. 실제 MSRC trace 실험

입력은 `prxy_0`에서 변환한 첫 500,000개 요청이며 원래 시간 간격을 유지했다.

| 설정 | 값 |
|---|---:|
| SSD 수 | 4 |
| stripe | 512 LBA |
| zone | 32,768 LBA = 16 MiB |
| SWANS threshold | 5 / 15 |
| epoch | 40 s |
| OP | 20% |
| P/E limit | 10,000 |
| SSD cache mode | OFF |

결과:

| 지표 | 결과 |
|---|---:|
| 생성/완료 요청 | 500,000 / 500,000 |
| read / write 요청 | 33,330 / 466,670 |
| 평균 device response time | 910 us |
| 마지막 μ | 5.813900 |
| redirect operations | 69 |
| migration operations | 0 |
| WAM host writes | 2,234,669 sectors = 1,091.15 MiB |
| WAM migration writes | 0 |
| WAM cumulative writes | 2,234,669 sectors |
| flash page programs | 527,755 |
| approximate flash WAF | 3.778671 |
| bad block | 0 |
| OP exhausted | false |

이 trace 구간에서는 μ가 critical 15에 도달하지 않아 migration은 발생하지 않았다. 이는 오류가 아니라 현재 논문 권장 임계값과 OP 20% 조건의 결과이며, redirect만으로 마지막 μ가 5.81까지 낮아졌다.

## 3. migration WAM 강제 경로 검증

실제 trace와 나머지 설정은 유지하고 **기능 검증 목적으로만** critical threshold를 5.5로 낮춰 migration 경로를 실행했다. 이 결과는 성능 비교값으로 사용하면 안 된다.

| 지표 | 결과 |
|---|---:|
| 완료 요청 | 500,000 |
| redirect / migration | 2 / 4 |
| background read / write I/O | 10 / 10 |
| WAM host writes | 2,234,669 sectors |
| WAM migration writes | 40,960 sectors = 20 MiB |
| WAM cumulative writes | 2,275,629 sectors = 1,111.15 MiB |
| migration 추가량 / host writes | 1.8329% |

검산:

```text
2,234,669 + 40,960 = 2,275,629 sectors
```

SSD별 migration write도 `0, 8,192, 24,576, 8,192 sectors`로 기록되어 합계가 40,960 sectors와 일치했다.

## 4. read/write 공통 대기 검증

첫 migration이 시작되는 40초 직후 hot zone 40에 read 100개와 write 100개를 교차 삽입한 검증 trace를 사용했다.

| 지표 | 결과 |
|---|---:|
| 전체 요청 | 1,633 |
| migration operations | 4 |
| migration 중 deferred requests | 64 |
| deferred writes | 32 |
| deferred reads | 32 (`64 - 32`) |
| backend replay requests | 64 |
| RAM에서 조기 완료된 write | 0 |

따라서 queue 한도 내에서 read와 write가 함께 기다렸고, 64개 모두 migration 후 backend로 다시 제출됐다.

## 5. bad block 및 OP 종료 검증

실제 수명 예측이 아닌 종료 경로 검증을 위해 SSD 1개, 256 blocks, OP 20%, P/E limit 1의 작은 stress 설정을 사용했다.

| 지표 | 결과 |
|---|---:|
| OP spare limit | `ceil(256 × 0.2) = 52 blocks` |
| erase 완료 후 bad 처리 | 43 blocks |
| 수명 한계 도달 확정 in-flight erase | 9 blocks |
| OP consumed | 52 blocks |
| OP exhausted | true |
| 종료 시각 | 1,290,655,016 ns |
| 예정 요청 | 50,000 |
| 종료 전 생성 / 완료 | 641 / 633 |

`43 + 9 = 52`가 OP 한도에 도달하는 순간 시뮬레이션이 정상 종료됐다. P/E limit 1은 기능 검증을 빠르게 하기 위한 값이며 실제 SSD 수명 결과로 해석하면 안 된다.

## 6. 이전 cached 결과와 참고 비교

이전 결과는 cache `WRITE_CACHE`, OP 10%였고 새 결과는 cache OFF, OP 20%이므로 순수한 한 변수 A/B 비교는 아니다.

| 지표 | 이전 cached/OP10 | 새 no-cache/OP20 |
|---|---:|---:|
| 평균 device response | 42 us | 910 us |
| flash page programs | 185,935 | 527,755 |
| approximate flash WAF | 1.331275 | 3.778671 |
| redirect / migration | 97 / 1 | 69 / 0 |

캐시를 끄면서 write coalescing과 빠른 cache completion이 사라져 response time과 flash program 수가 증가했다. 이 변화는 요청한 no-cache 의미에 부합하지만, 이전 결과와의 차이에는 OP 및 WAM 계산 방식 변경도 함께 포함된다.
