# 연구실 SWANS 코드 `src2_0` 실행 분석

실행일: 2026-08-28

## 실험 조건

- Trace: MSRC `src2_0.csv` 전체를 MQSim 5열 trace로 변환
- 요청 수: 1,557,814
- 시간 가속: 16배
- SSD 수: 4
- RAID stripe: 512 LBA
- SWANS zone: 16,384 LBA
- SWANS epoch: 40초
- 임계값: precautionary 3, critical 6
- Preconditioning: 비활성화

비교군은 동일한 연구실 코드와 4개 SSD에서 `SWANS_Enabled=false`만 적용한 RAID0이다.

## 실행 완료 여부

SWANS와 RAID0 모두 1,557,814개 요청을 생성하고 전부 완료했다. 종료 시 inflight request, inflight sub-request, migrating zone, duplicate physical mapping은 모두 0이었다.

## Migration 분석

- epoch 평가: 1,092회
- migration epoch: 1,092회
- normal/redirect epoch: 0회
- migration operation: 1,092회
- 모든 migration의 hot logical zone: **zone 376 하나뿐**
- 첫 이동: SSD 0 → SSD 2
- 이후: SSD 2 → SSD 1 546회, SSD 1 → SSD 2 545회
- 복사 block: 4,325개
- 복사 sector: 17,715,200 sector
- migration 복사량은 host write sector의 약 90.4%
- background read I/O: 4,325
- background write I/O: 4,434
- migration 충돌로 buffering/replay된 요청: 372

즉 migration 기능 자체는 완료됐지만, 동일한 zone 376이 SSD 1과 SSD 2 사이에서 매 epoch 왕복했다. 이는 정상적인 수렴이 아니라 ping-pong이다.

## 판단

### 정상 동작으로 확인된 부분

- 전체 trace 요청 완료
- migration background read/write 완료
- source discard 완료
- migration 중 충돌 write buffering 및 replay 완료
- 종료 시 mapping 중복과 active migration 없음
- SSD별 sector 분포는 RAID0보다 균등해짐

### 정책 결함으로 판단되는 부분

- 모든 epoch에서 migration 수행
- 동일 zone을 1,092회 반복 이동
- μ가 critical 이하로 안정적으로 내려가지 않음
- flash write가 RAID0보다 83.6% 증가
- 최대 latency가 67.3% 증가

현재 구현은 migration 이후 예상 μ가 감소하는지 확인하지 않고 hot zone의 누적 write 기여량을 새 SSD로 통째로 이전한다. 그 결과 hot/cold SSD 관계가 반대로 뒤집혀 다음 epoch에 동일 zone을 되돌린다.
