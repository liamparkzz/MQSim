# 공용 변환 설정 추천 초안

**검토용 v1 — 아직 실험 조건으로 확정하지 않음.** Alibaba를 제외한 6개 자료 항목을 원본 MQSim에 입력하기 위한 변환 설정이다. 변환기 **1.0.0**에서 읽을 수 있는 `batch.review.json`과 용량 계산 근거를 함께 제공한다.

## 1. 먼저 확인할 공통값

| 항목 | 추천값 | 의미 |
|---|---|---|
| NAND 데이터 물리 용량 | **256GiB = 274,877,906,944B** | 페이지 메타데이터 448B는 데이터 용량 계산에서 제외 |
| OP | **물리 용량의 7%** | 현재 기본 XML의 OP 비율 유지 |
| 변환 검사 용량 | **255,636,439,040B** | 약 255.636GB / 238.079987GiB. 모든 작업에 동일하게 지정 |
| 변환기 `capacity` 값 | `255636439040B` | 물리 용량이 아닌 아래에서 계산한 논리 주소 한도 |
| 실험 실행 단위 | 파일별 독립 실행, NVMe 흐름 1개, 모든 NAND 자원 사용 | 6개 파일을 동시에 6개 흐름으로 실행하면 용량을 다시 계산해야 함 |
| 원본 장치 | 파일당 1개 장치 명시 | 출력 장치 번호는 0. 장치·파일 간 주소를 합치지 않음 |
| 출력 단위 | 시간 ns, 주소·크기 512B 섹터 | 쓰기 0 / 읽기 1 |
| 시간 기준 | 첫 선택 요청을 0으로 이동 | 실제 간격 유지. 시간 압축 없음 |
| 주소 | 그대로 보존, 요청 끝 주소까지 검사 | 한도 초과 시 해당 파일 실패 |
| 요청 | 전체 요청 1회, R/W 비율·크기 보존 | 반복·샘플링·요청 분할·병합·설치/실행 구간 연결 없음 |
| 비정상 데이터 | 오류 | 잘못된 행·알 수 없는 명령·정렬하지 않은 시간 역전을 건너뛰지 않음 |

추천하는 용량 구성은 다음과 같다.

```text
8 채널 × 채널당 2칩 × 칩당 2다이 × 다이당 2플레인
× 플레인당 2,048블록 × 블록당 256페이지 × 페이지당 8,192B
= 256GiB
```

현재 저장소의 `ssdconfig.xml`은 채널당 **4칩**, 계산상 **512GiB**다. 위 256GiB를 시뮬레이션에 적용할 때는 별도 SSD 설정에서 채널당 칩 수를 **2**로 바꾸고 각 흐름의 칩 ID를 **0, 1**로 맞춰야 한다. 이 초안은 용량 구성을 제안하며 기존 SSD XML을 수정하지 않았다.

MQSim의 흐름별 주소 할당 코드에 따라 플레인마다 OP를 뺀 섹터 수를 먼저 정수로 내린다.

```text
64플레인 × floor(2,048 × 256 × 16섹터 × 0.93) × 512B
= 64 × 7,801,405 × 512B
= 255,636,439,040B
```

유효 LBA는 **0 ~ 499,289,919**다. 요청 끝을 포함해 이 범위를 검사한다. 기준 코드는 `src/utils/Logical_Address_Partitioning_Unit.cpp`의 `Allocate_logical_address_for_flows`와 `Get_total_device_lha_count`다. 전체 페이지 수에 OP를 한 번 적용하는 AMU의 별도 계산값은 8,192B 더 크므로 이 설정의 용량 한도로 사용하지 않는다. 경계 주소 도우미의 `+1` 관례로 검사 용량에 한 섹터를 더하지 않는다. 계산값과 소스 해시는 `capacity.reference.json`에 기록했다.

## 2. 파일별 추천값과 현재 상태

| 자료 | 초안의 입력 파일 | 원본 장치 | 시간 정렬 | 1ns 미만 | 용량 확인 |
|---|---|---|---|---|---|
| RocksDB overwritezipf | `rocksdb_overwritezipf_200000000_500000x8.csv` | `0` | 안 함 | 오류 | **초과** |
| RocksDB YCSB-A | `rocksdb_ycsb-a_200000000_500000x8.csv` | `0` | 안 함 | 오류 | **초과** |
| Mobile | `diablo_exec.csv.gz` | `8388608` | 안정 정렬 | `floor` 내림 | 범위 내 |
| MSRC_1 | `CAMWEBDEV-lvm3.csv` | `wdev:3` | 안 함 | 오류 | 범위 내 |
| MSRC_2 | `rsrch_1.csv` | `rsrch:1` | 안 함 | 오류 | 범위 내 |
| CloudPhysics | `SELECT_ORIGINAL_TRACE.vscsitrace` | `0` | 안정 정렬 | 오류 | **전체 원본 미확보** |

Mobile·MSRC 입력은 기존 변환 검증에 사용한 파일을 **임시로 지정**했다. 각 폴더 전체를 선택한 것이 아니다. MSRC_1 입력은 쓰기 약 3MB, MSRC_2 입력은 약 171MB로, GC/WL 실험용 대표 파일 선정은 추가 검토가 필요하다. 이 작은 입력만으로 GC/WL이 충분히 발생할 것이라고 기대하지 않는다. Mobile의 설치 구간과 다른 앱도 현재 초안에 포함하지 않았다.

Mobile 정렬은 같은 시각의 요청에서 원본 순서를 유지한다. `floor`는 원본 절대 시각을 정수 ns로 내린 뒤 첫 요청을 0으로 옮긴다. 원본 시각당 손실은 1ns 미만이며 영향받은 행 수를 보고서에 남긴다. 다른 자료에서 1ns 미만 값이 새로 발견되면 오류로 확인한다.

CloudPhysics 항목은 **원본 VSCSI** 기준이다. 공개 파서 검증 샘플을 전체 원본 대신 넣지 않았다. CSV를 선택한다면 `format`을 바꾸고 검증된 `length_unit`을 명시해야 한다.

## 3. 이번 검토에서 결정할 부분

1. **위 NAND 구성과 OP 7%**를 공통 용량 기준으로 사용할지 확인한다.
2. **RocksDB 초과 주소 처리:** 현재 추천 기본값은 주소 보존·초과 시 오류다. overwritezipf는 최소 274,853,789,696B, YCSB-A는 274,878,955,520B가 필요하다. 두 파일 모두 이 논리 용량으로 그대로 실행할 수 없다. 용량 축소·주소 재배치가 필요하면 방법을 먼저 합의하고 별도 변환 규칙으로 구현해야 한다. 원본 요청을 버리거나 주소를 접어 넣는 옵션은 이 초안에 없다.
3. **실제 사용할 Mobile·MSRC 파일과 CloudPhysics 원본**을 확정한다. 파일을 바꾸면 원본 해시·장치 번호·주소 범위도 다시 확인한다.

GC/WL 정책·임계값, 초기 점유율, 사전 채우기와 SSD 캐시는 이 변환 설정에서 확정하지 않는다. 해당 값은 이후 시뮬레이션 설정에 고정해야 한다.

## 4. 들어 있는 파일과 검증 범위

- `batch.review.json`: 변환기에서 읽는 설정. 입력·출력 경로는 **이 JSON의 위치**가 기준이다.
- `capacity.reference.json`: 추천 NAND 구성, 용량 계산, 적용 전제와 소스 해시. MQSim이나 변환기가 직접 읽는 설정은 아니다.
- `inputs.lock.json`: 원본 5개의 파일명·크기·SHA-256, CloudPhysics 미확보 상태. **변환기 1.0.0은 이 목록을 자동으로 읽어 해시를 강제 검사하지 않는다.** 팀에서 원본이나 변환 보고서의 `source.sha256`과 대조한다.
- `preflight.review.json`: 설정 구문, 경로, 원본 해시와 기존 전체 스캔 결과에 따른 용량 비교 기록.

설정은 변환기 1.0.0의 실제 배치 로더에 읽혀 6개 작업의 옵션이 전달되는 것을 확인했다. 이 확인에서는 변환 함수를 실행하지 않았다. 원본 5개 전체의 SHA-256을 다시 계산해 기존 검증 기록과 일치함을 확인했다. **용량 범위 내 3개, 범위 초과 2개, 입력 미확보 1개**다. 이번 초안으로 대량 변환이나 시뮬레이션을 실행하지 않았다.

팀에 공유할 때 이 폴더 전체와 변환기 1.0.0을 함께 전달한다. 설정 ZIP은 변환기 폴더에 풀면 `profiles/review-256gib-op7-v1/`로 배치된다. 현재 경로는 `MQsimDT/tools/trace_converter/`와 `MQsimDT/Trace/` 배치를 기준으로 한다. 다른 배치를 사용하는 팀원은 `input`·`output` 경로만 자신의 폴더에 맞추고, 나머지 값과 원본 해시는 동일하게 유지한다.

검토 후 변환기 폴더에서 사용할 명령은 다음과 같다. **현재 그대로 실행하면 RocksDB 2개는 용량 오류, CloudPhysics는 파일 없음 오류가 발생하고, 나머지 작업은 처리된다.**

```text
python mqsim_trace_converter.py batch "profiles/review-256gib-op7-v1/batch.review.json"
```

GUI의 개별 파일 선택 화면은 이 JSON을 불러오지 않는다. 공용 설정을 그대로 적용할 때는 위 배치 실행을 사용한다. 출력은 `Trace/converted/review-256gib-op7-v1/`에 파일별로 생성되며 기존 결과는 덮어쓰지 않는다.
