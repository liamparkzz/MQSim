# gun_swans 버전별 변경 및 MSRC_2 실험 현황

## 현재 결론

- 전체 MSRC_2 트레이스 실행은 2026-08-29 사용자 요청으로 보류했다.
- 정상 완료되어 결과 XML이 존재하는 트레이스는 **19개**다.
- `proj_1`, `proj_2`, `src1_0`, `usr_1`, `usr_2`는 결과 XML이 없으므로 통합 Excel의 결과 행에서 제외한다.
- Excel은 완료된 모든 트레이스에 동일한 열·단위·수식·시트 포맷을 적용한다.
- 완료된 19개 결과는 모두 `gun_swans_v1_epochlog` 바이너리에서 생성됐다. v1.1~v1.3은 대형 트레이스 오류를 분석하며 만든 후속 수정본이고 완료 결과에는 아직 사용되지 않았다.

## 버전별 변경 사항

### 0. 기반 gun_swans: WAM + no-cache + OP/endurance

연구실 SWANS 코드에 다음 요구를 반영한 기반이다.

- host write와 migration restore write를 sector 단위로 분리·누적한다.
- `WAM_Cumulative_Write_Sectors = Host + Migration`으로 계산한다.
- migration 대상 write도 read와 함께 대기하며 RAM에서 조기 완료하지 않는다.
- RAID/SSD device cache를 사용하지 않는다.
- block erase count가 P/E limit에 도달하면 bad block으로 retire한다.
- retire된 block과 retire 예정 in-flight block이 OP 예비 block 한도에 도달하면 시뮬레이션을 종료한다.
- OP 고갈 순간의 상태를 보존한다.

### 1. `gun_swans_v1_epochlog`

실제 완료 결과 19개를 만든 버전이다.

주요 변경:

- 참조 이미지에서 요구한 아래 9개 EOL/수명 값을 XML에 추가했다.
  - `EOL_Triggered`
  - `First_EOL_SSD_ID`
  - `EOL_Time`
  - `EOL_Bad_Block_Count`
  - `EOL_Effective_OP_Ratio`
  - `Bad_Block_Count`
  - `Current_Effective_OP_Ratio`
  - `Max_Block_Erase_Count`
  - `Total_Block_Erase_Count`
- 40초 epoch마다 `SWANS_Epoch_Record`를 기록한다.
- epoch 로그에 μ, 상태(`NORMAL/REDIRECT/MIGRATION`), hot/cold SSD, migration 후보 수를 넣었다.
- SSD별 host/migration/cumulative write sector와 누적 write share를 기록한다.
- migration history와 WAM, SSD별 OP/bad-block/erase 통계를 XML로 출력한다.

바이너리 SHA-256:

`D97BFB3E62C0235EEC70D87EA22C056DC7650F38B4DA6C7FA28A851D925B794F`

### 2. `gun_swans_v1_1_gcwl_fix`

정적 wear-leveling 후보를 시작 상태로 표시할 때 block ID 하나만 넘겨 잘못된 channel/chip/die/plane 주소가 만들어지던 문제를 수정했다.

변경 전 개념:

```cpp
GC_WL_started(wl_candidate_block_id);
```

변경 후 개념:

```cpp
GC_WL_started(wl_candidate_address);
```

효과:

- 실제 선택한 SSD 내부의 정확한 물리 block에 `Has_ongoing_gc_wl`을 설정한다.
- 다른 주소를 잠근 채 동일 LPA가 다시 선택될 가능성을 줄인다.

바이너리 SHA-256:

`042846C21E77361733C88D206DF54FF9DFEE3AA08CC564FA0148B51EC94198FB`

상태: 빌드 성공. 대형 트레이스 완료 결과는 없음.

### 3. `gun_swans_v1_2_gcwl_barrier_guard`

`src1_0`에서 발생한 `Locking an LPA that has already been locked` 오류를 막기 위해 추가했다.

주요 변경:

- GC/WL 후보 block의 모든 valid page metadata를 확인한다.
- 그 block 안에 이미 이동 중인 LPA 또는 MVPN이 있으면 새 barrier를 걸지 않는다.
- page-level mapping에는 실제 검사 함수를 추가하고 hybrid mapping에는 호환 구현을 추가했다.

바이너리 SHA-256:

`C8845EA4D672F224A14B2F0E03A304D2F6A66E67F0F1D9FA632B68BE42D6BFFA`

상태:

- 50만 요청 검증 트레이스는 100% 정상 완료했다.
- `proj_1` 대형 트레이스는 40% 이후 host completion이 증가하지 않는 상태가 관측되어 결과 XML을 만들지 못했다.

### 4. `gun_swans_v1_3_gc_candidate_fallback`

v1.2에서 잠긴 후보를 발견하고 단순히 반환하면, GC hard threshold 때문에 host write가 정지한 plane에서 재시도 계기가 사라질 수 있다는 점을 보완한 버전이다.

주요 변경:

- RGA가 선택한 후보에 잠긴 LPA/MVPN이 있으면 같은 plane 전체를 검사한다.
- full block, invalid page 존재, bad block 아님, 진행 중 GC/WL 아님, write frontier 아님, 잠긴 page 없음 조건을 만족하는 후보만 허용한다.
- 조건을 만족하는 후보 중 invalid page가 가장 많은 block을 fallback 후보로 사용한다.

바이너리 SHA-256:

`57E81C7DEDC2C6126F21BA3409D3CA5AD14DE841EEC5577C31C118265975181A`

상태: **컴파일만 성공했으며 트레이스 실행은 사용자 요청으로 보류했다. 결과 해석에 사용하면 안 된다.**
